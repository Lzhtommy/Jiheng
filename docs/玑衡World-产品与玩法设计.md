# 玑衡 World：产业链探索游戏设计

> 版本：2026-09-22 · 当前实现方向
>
> 本文是「玑衡 AI」探索主线的最新产品与玩法文档。它描述的是用户作为小白探索公司产业链的 World 形态，不是 CEO 模拟器，也不是把研究报告换成卡片的展示页。

## 一句话定位

**用户作为一名产业链探索者，站在公司世界的中央，点击上下游节点进入现场，通过调查、选择和反馈，亲手拼出一家公司如何受到产业链事件影响。**

## 核心体验

玑衡 World 的最小学习闭环是：

```text
站在公司世界中央
  → 点击一个产业链节点
  → 进入该节点的独立场景
  → 调查现场物件 / 角色 / 证据
  → 把线索带到证据桌，观察它们如何连接
  → 得到通俗解释与因果链反馈
  → 返回主地图，点亮该节点
```

主地图负责“我下一步去哪儿”；独立场景负责“我在这里学会什么”。

World v2 的核心原则是：**不把每个场景做成选择题。用户通过观察、点击、比较和连接线索来理解产业链，题目只保留给最后的风险挑战。**

## 用户身份

用户不是旁观者，也不是 CEO，而是：

> **产业链探索者 / 投研学徒**

用户拥有一个位于地图中央的主人公形象。每个产业链节点都是一个可以进入的地点，用户通过自己的点击和选择推动调查，不由 Agent 代替完成。

### 用户应该感受到的事情

- 我正在调查一家公司，而不是阅读百科；
- 我先提出自己的猜测，再用证据修正它；
- 我能看到一个事件如何从上游传到下游；
- 我完成探索后，能用自己的话讲清楚一条影响链。

## 主地图：公司世界大厅

主地图以用户为中心，节点围绕用户分布：

```text
                 上游资源
                    │
       中游材料 ── 你 ── 核心制造
                    │
                 下游需求
```

当前演示世界为「宁德时代 · 电池环城」：

| 节点 | 地点 | 用户进入后要理解什么 |
| --- | --- | --- |
| 上游资源 | 盐湖矿区 | 原材料价格是冲击的起点，但不等于利润结果 |
| 中游材料 | 材料工坊 | 库存、长协和配方会形成成本传导缓冲 |
| 核心制造 | 电芯城 | 财务结果需要拆回产业链原因 |
| 下游客户 | 车企港 | 需求和议价能力决定成本能否继续传导 |
| 第二需求 | 储能灯塔 | 多元场景可能分散单一终端风险，但不自动抵消风险 |

### 节点状态

- **未探索**：可见但处于雾化状态，提示“进入调查”；
- **已进入**：正在独立场景中调查；
- **已点亮**：用户完成该节点的调查，地图线路亮起，证据进入背包；
- **已复访**：可以重新进入查看线索，但不会重复计数。

## 独立场景：每个节点是一关

点击地图节点后，不在地图上直接展开长段文字，而是进入该节点的独立互动场景。

每个场景包含四个部分：

1. **现场引子**：用一个具体事件把用户带进去；
2. **可调查对象**：最多 3 个，用户点击后获得通俗线索；
3. **证据桌**：已发现的线索按发现顺序来到用户面前，逐渐组成一条影响链；
4. **发现反馈**：Agent 解释用户刚刚看到的关系，并生成一条可回到地图的证据。

### 场景模板

```text
场景标题：盐湖矿区
现场引子：矿区的价格看板刚刚跳动，影响从哪里开始？

可调查对象：
  - 价格看板：确认价格变化是事实
  - 矿区产能：理解供给变化不等于公司成本变化
  - 采购合同：了解价格如何进入采购端

证据桌：价格变化 → 采购成本压力
发现反馈：价格冲击首先进入上游采购成本，还不等于电池公司利润立刻下降。
```

## 四段探索章节

四段是地图上的四条主链路；其中下游章节包含两个地点。

### 01 上游资源：盐湖矿区

问题：**碳酸锂上涨 30%，冲击首先落在哪里？**

小白要带走的概念：原材料价格是成本冲击的起点，但不能直接跳到利润结论。

### 02 中游材料：材料工坊

问题：**为什么原料涨价不会马上变成电芯成本上涨？**

小白要带走的概念：库存、长期合同和配方差异会让传导产生滞后和差异。

### 03 核心制造：电芯城

问题：**看到利润变化，能直接说是锂价造成的吗？**

小白要带走的概念：财务指标说明“发生了什么”，产业链证据帮助解释“为什么发生”。

### 04 下游应用：车企港与储能灯塔

问题：**电池厂能不能把成本转嫁给客户？**

小白要带走的概念：需求强度、供需关系、合同机制和业务多元化决定传导出口。

## Agent 的位置

Agent 是同行者和角色化的研究工具，不是替用户游玩的主角。

| 角色 | 在场景中的行为 |
| --- | --- |
| 墨 · 档案官 | 介绍调查任务、提醒事实与推断的区别 |
| 岚 · 上游巡游者 | 提供资源、材料和成本线索 |
| 澈 · 需求观察员 | 提供客户、需求和议价线索 |
| 赤 · 风险猎人 | 在用户形成结论后提出反例 |

Agent 的回答必须附在线索或反馈上，不能用一段泛泛聊天替代用户行动。

## 证据表达

每个场景的线索分为两类：

- **硬数据**：财务字段、公告、合同条款、行业数据、历史价格等，带来源和时间；
- **AI 推断**：基于多个证据形成的解释或假设，必须明确标注，不能伪装成事实。

用户可以在地图的证据背包里打开“只看硬数据”，把故事拆成可核验的事实。

## 第一版实现范围

### P0：本地可玩的完整闭环

- 一个中央主人公；
- 5 个可点击产业链节点；
- 5 个独立场景，复用统一场景模板；
- 每个场景 3 个可调查对象；
- 每个场景 1 个证据桌和发现反馈，不在场景中强制答题；
- 完成后返回主地图并点亮节点；
- 线索进入证据背包，区分硬数据与 AI 推断；
- 结束后生成一张“我的产业链理解卡”。

### P1：增强可玩性

- 角色在场景中行走到调查对象旁边；
- 事件冲击波沿地图线路传播；
- 根据用户选择生成不同的后续问题；
- 多 Agent 在用户结论后进行可观看的争论；
- 从 World 一键跳转到 Research 专业证据页。

## 完成标准

用户完成第一关后，应该能够回答：

1. 冲击从哪里开始？
2. 中间有哪些缓冲环节？
3. 什么条件下才会真正影响公司的利润？

如果用户只是看完了五个节点，却无法回答这三个问题，说明产品仍然是信息展示，不是有效的探索学习。

## 和 Research 的连接

World 里的每个场景线索，都应该能映射回 Research 的证据：

```text
World 场景物件
  → 证据 ID
  → 来源 / 日期 / 字段
  → Research 中的完整解释、反例与待验证问题
```

World 负责让小白愿意探索、敢于判断；Research 负责让判断可以被核验、被反驳、被继续研究。

## 当前开发结论

现有四章分页可以保留，但分页不再是主要交互。World v2 的核心改造是：

> **把每个产业链节点做成一个可以进入、可以调查、可以观察线索连接、可以带着发现离开的独立现场。**

## World v2：调查版界面

World v2 保留旧版作为对照，但使用新的“现场调查”结构：

- **世界大厅**：中央主人公、上下游节点、雾化未开放节点、真实上下游连线；
- **现场页**：用户自己的角色进入一个产业链现场，墨只做轻量提示；
- **物件调查**：点击价格看板、库存仓、合同、订单等对象，查看事实或推断；
- **证据桌**：线索按发现顺序排列，用户可以直观看见“价格 → 成本 → 产品 → 需求”的传导；
- **回到地图**：完成现场调查后节点点亮，线路继续向下游延伸；
- **风险挑战**：只有完成完整产业链后，才出现一次可选的风险压力测试，不把它变成每个场景的考试。
