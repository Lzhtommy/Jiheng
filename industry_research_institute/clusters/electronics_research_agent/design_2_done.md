# 电子行业研究集群实施方案  
（LangGraph + LangChain，无代码）

## 目的

把已定方案落成可运行系统：按申万电子编制自动研究，编译出可对账的研究报告；人只在终审出现，不通过则由图按最小范围重写。

LangGraph 负责阶段、并行分派、中断终审、重写路由和落盘恢复。  
LangChain 负责模型调用、结构化输出、提示词和工具。  
分派、政策注入、闸门是图里的确定性步骤，不交给模型。

---

## 1. 运行时怎么拆

整条流水线是一张主图，下面挂四张子图。

| 图 | 职责 |
|----|------|
| 主图 | 读宪法、选宇宙、映射、扇出、汇总、送审、终审中断、按裁决跳转、发布或停机 |
| L3 子图 | 单槽研究员：写公司卡、L3 笔记、主张、最多 5 条产业链事实 |
| L2 子图 | 单槽主管：读直属笔记摘要，写对照结论与抽检 |
| L1 子图 | 首席：读各 L2 摘要，写总纲、冲突、优先级 |
| 报告子图 | 写手：只读已过闸门的状态，编译固定目录报告 |

主图保存控制面：本轮配置、分派表、各工件编号、阶段、重写计划、预算、终审裁决。  
大工件（公司卡、笔记、报告正文）进对象存储或 `runs/{run_id}/`，状态里只留编号。并行扇出时用列表追加，避免互相覆盖。

隔离靠「子图只收到本槽数据包」实现，不靠提示词里的禁令。

## 2. 一次成稿的阶段

1. 开机：生成 `run_id`，读树、政策卡、成分表、可选景气钟，写入本轮配置。  
2. 选宇宙：默认电子成分；可按二级、三级、代码列表或冒烟夹具过滤。  
3. 映射闸门：代码落到唯一 L3；表外代码按策略拒绝或标未映射。失败则整轮封闭。  
4. 扇出 L3：每个三级（含 0 票空槽）各开一个 L3 子图。  
5. 收齐后扇出 L2：每个二级只拿直属三级笔记编号与摘要。  
6. L1：只拿各二级综述。  
7. 编译报告。  
8. 送审闸门：对账、覆盖、证据、冲突、套模板。不过则先在报告层重编译，仍不过则停或下钻。  
9. 人终审：图在此中断，线程挂起。  
10. 通过则发布；不通过则生成最小重写计划，跳回对应阶段；超限或证据不足则停机落盘。

巡检模式走 1–6 和清单落盘，不进报告子图、不中断等人。成稿模式走完全程。关模型时拓扑不变，判断字段填「待定」。

## 3. 节点清单（主图）

按执行顺序，名称即实现任务。

| 节点 | 类型 | 做什么 |
|------|------|--------|
| 读宪法 | 代码 | 加载申万树、政策 YAML、成分表、时钟、夹具开关 |
| 解析宇宙 | 代码 | 得到本轮股票集合与过滤声明 |
| 映射分派 | 代码 | 产出 L3→股票表、空槽表、未映射表 |
| 预检 | 代码 | 分派完整性、政策能否命中、输入结构 |
| 调度 L3 | 路由 | 按分派表并行启动子图 |
| 汇总 L3 | 代码 | 校验笔记齐套，写入产业链黑板 |
| 调度 L2 | 路由 | 按二级并行启动子图 |
| 汇总 L2 | 代码 | 校验各二级都有对照结论 |
| 跑 L1 | 子图 | 产出总纲 |
| 编译报告 | 子图 | 产出成稿与主张-证据表 |
| 送审闸门 | 代码 | §8 全部检查 |
| 终审中断 | 人机 | 把报告、证据表、清单推给人 |
| 解释裁决 | 代码 | 无码则退回补码；有码则生成重写计划 |
| 执行重写 | 路由 | 按范围跳回编译 / L1 / 某 L2 / 某 L3 |
| 发布 | 代码 | 冻结清单、写 diff、标记已发布 |
| 停机 | 代码 | 未通过稿 + 失败码落盘 |

条件边只看阶段、闸门结果、裁决范围和预算，不看模型自评。

## 4. 子图内部

### 4.1 L3

顺序：取本槽数据包 → 拉数（可选工具） → 填公司卡数字与归属（代码优先） → 写判断与主张（模型或待定） → 抽取至多 5 条产业链事实 → 本槽校验 → 返回笔记编号。

本槽校验：主指标与卡一致、未切片已声明、时钟若存在则已应答、主张有证据结构、没有写进其它三级的股票。

空槽：不写公司卡，只写家数为 0 的笔记，直接返回。

### 4.2 L2

输入只有直属笔记的结构化摘要、本级政策、黑板只读视图、本槽重写约束。  
产出对照结论、政策抽检、本级位置、主张列表。  
禁止把下属笔记首尾相接当成综述。

### 4.3 L1

输入各二级综述、时钟、黑板聚合、本轮过滤声明。  
产出跨级冲突点名、关注优先级、样本边界（即本轮过滤）。  
冲突在状态里已存在而此处写顺，本节点失败。

### 4.4 报告

输入：总纲、二级综述、主张表、清单、过滤声明、上轮 diff（若有）。  
固定六章：结论、证据、情景、冲突与未决、样本边界、附录来源。  
写手工具只有「读已落盘字段」，没有改政策、没有补票、没有改原始数字。待定不得写成定论。

## 5. LangChain 怎么用

每个会写判断的节点配三件套：系统提示（角色 + 本槽可见输入说明）、结构化输出（与工件字段一一对应）、可选工具。

工具分三类：

- 只读行情/财报查询：按本槽股票列表过滤，查到的键进入出处。  
- 读政策卡：返回本槽已注入的卡，不能改文件。  
- 读黑板：按本链相关事实过滤。  

模型只填判断、叙事、主张、证据引用。数字、归属、政策编号由代码写入后作为输入展示给模型，模型改了也过不了节点校验。

关模型：同一套结构用规则填充，判断为待定，后续节点照常。

提示词按 L3/L2/L1/写手四套模板，用槽位名和本轮约束注入，不按「17 只票」写死业务。

## 6. 并行与隔离

L3、L2 用「按键扇出」：有几个槽就起几个子图，互不等待，结果追加回主状态。  
每个子图的数据包只含：本槽编号、本槽股票或直属摘要、本槽政策、本轮时钟、与本槽有关的黑板条目、与本槽有关的重写约束。

实现验收：单测构造两个三级，断言甲的模型输入对象里没有乙的股票列表。不测「磁盘上文件谁能打开」。

---

## 7. 终审中断

送审闸门通过后，主图进入中断节点，线程写入检查点，进程可以退出。

推给人的只有三件：报告正文、主张-证据表、本轮清单（宇宙、过滤、版本、空槽、失败槽）。

人返回一张裁决：通过或驳回、范围、原因码、必须改、禁止再出现。缺原因码则仍停在终审，请人补码，不启动重写。

恢复时用同一线程号继续。检查点必须能在重写中途再次中断（第二次终审）。

---

## 8. 重写路由

解释裁决节点产出重写计划后，主图按范围跳转，其它槽的工件编号保留。

| 范围 | 跳回 | 随后自动重跑 |
|------|------|----------------|
| 仅报告 | 编译报告 | 送审闸门 → 终审 |
| 首席 | L1 子图 | 编译 → 闸门 → 终审 |
| 某二级 | 该 L2 子图 | L1 → 编译 → 闸门 → 终审 |
| 某三级 | 该 L3 子图 | 所属 L2 → L1 → 编译 → 闸门 → 终审 |
| 无法机改 | 停机 | 无 |

冻结不变：归属、政策卡、本轮宇宙、库快照、已过闸门的原始数字。  
可变：判断、主张与证据、成文。

预算：人终审每篇两次；同一槽位每轮机器重写两次；编译层每轮两次。超限走停机节点。  
「证据不足 / 需改政策或归属」直接停机，不空转。

重写约束只注入被点名的子图和写手，不广播到兄弟槽。

## 9. 持久化

三种存储，职责分开。

| 存储 | 内容 |
|------|------|
| 检查点 | 主图控制面、中断位置、预算、裁决，供崩溃恢复与终审唤醒 |
| 文档库 | 产业链黑板、跨轮已校验约束、已发布时钟段 |
| 文件树 `runs/{run_id}/` | 公司卡、笔记、综述、总纲、报告、清单、裁决、重写计划、与上轮 diff |

发布节点把清单里的版本钉死，并打已发布标记。下一次成稿可只读引用上轮已发布总纲中的时钟段和 diff。

检查点与文件树用同一 `run_id`。命令行唤醒终审、查询状态、导出报告都只认这个编号。

## 10. 命令行（实现必须提供）

- 跑巡检 / 成稿（全量、按二级、按三级、按代码、按夹具）  
- 打印编制树、映射一只代码、打印生产宇宙规模与按三级计数  
- 列出等待终审的线程  
- 提交裁决并恢复图  
- 导出某次已发布报告与清单  

成稿默认开模型；巡检默认可关模型。数据库开关与夹具开关独立。

## 11. 工程落地顺序

### 第一期：能关模型跑通主图

实现宇宙、映射、分派、空槽、工件落盘、主图串到 L1、清单。  
测试：夹具分派全对、成分表一票一三级、上下文不串包、空槽不计覆盖。  
此期即可接命令行巡检。

### 第二期：子图 + 结构化模型输出

接 L3/L2/L1/写手四套提示与结构校验；数字仍由代码填。  
报告对账：正文关键数字和点名股票不超出状态与宇宙。  
巡检与成稿分流。

### 第三期：中断终审与最小重写

检查点、终审命令、原因码路由、预算、停机。  
测试：无码不重写；只改报告不动笔记；改一个三级只级联其上级；超限停止。

### 第四期：时钟、黑板、金标准回归

时钟只读注入与应答校验；黑板限额与只读视图；用若干篇已通过历史成稿回归「冲突必现、数字变则叙事变」。

第一期未绿，不开写手与终审。第三期未绿，不上发布流程。

## 12. 测试怎么钉在图上

| 层级 | 测什么 |
|------|--------|
| 域逻辑 | 映射、政策命中、空槽、未映射策略 |
| 节点 | 单节点输入输出契约，模型用假对象替换 |
| 子图 | 一个三级/二级的完整进出，断言看不见外槽股票 |
| 主图 | 关模型走完全程；开模型用假 LLM 走成稿 |
| 中断 | 停在终审、恢复通过、恢复驳回后的跳转 |
| 对账 | 故意在报告里写状态没有的数字，闸门必须拦 |
| 回归 | 夹具反例、金标准成稿的冲突节与 diff |

指标与方案正文一致：分派与政策 100%、假覆盖 0、送审对账 100%、核心结论必须有证据、夹具反例复发 0。发布率只观测。

## 13. 实施验收

系统可称为落地，当且仅当：

1. 默认跑的是电子成分或调用方给出的子集。  
2. 冒烟名单只出现在夹具命令里。  
3. 全树有槽，无票出空笔记且不算已研究。  
4. 各子图输入由分派裁剪。  
5. 政策只来自 YAML，本轮不改卡。  
6. 关模型能出齐状态和清单。  
7. 成稿核心结论能指回状态字段或查询出处。  
8. 报告数字与点名股票不超出本轮状态与宇宙。  
9. 人只能用带原因码的裁决恢复图。  
10. 重写按最小范围跳转，超限或不能机改则停并留失败码。  
11. 已发布报告首页写清本轮研究了谁，冲突与未决仍在成稿里。

---

## 14. 一句话对照

LangGraph 管「谁在哪一步、看见什么、人在哪停、驳回跳回哪」。  
LangChain 管「在允许的输入里把判断和报告写成规定结构」。  
代码闸门管「假口径、假覆盖、无出处的结论进不了终审」。  

三者叠在同一张主图上，才是本方案的实施形态。
