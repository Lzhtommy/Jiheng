# 电子行业研究院 Agent 集群：设计思路与方案

版本：v0.1.0
状态：已落地（结构化跑批可用；LLM 叙事未接）
对应目录：`industry_research_institute/clusters/electronics_research_agent/`

本文记录**为什么这样拆、一二三级如何配合、当前实现边界**。用法见 `README.md`，行业与政策真源见 `data/README.md`。

---

## 1. 设计目标

用申万 2021 **电子（270000）** 行业树，搭一个行研 agent 集群：

| 申万层级 | Agent 角色 | 判断对象 |
|----------|------------|----------|
| L1 一级 | 首席 | 电子行业周期、三个活跃二级的相对位置与冲突 |
| L2 二级 | 主管 | 本板块口径、下属三级是否可比、政策有没有用对 |
| L3 三级 | 研究员 | 本三级成分股的事实、财务、估值情景 |

另有一个**编排器**（代码，不是行业角色）：分派股票、发政策卡、强制自下而上写工件。

### 1.1 要解决的问题

电子不是同质行业。半导体设备看资本开支和 EV/EBITDA，芯片设计看 PE，电子化学品偏化工。一个「电子 agent」会把北方华创和三环集团用同一套口径讲完。拆开后：研究员只对自己的赛道负责；主管只做本二级内的口径与对比；首席只做跨二级配置，不改个股数字。

### 1.2 非目标（本版本）

- 不覆盖其它一级行业
- 不调用 `valuation_router.route()`
- 不把消费电子 / 光学光电子等未覆盖板块写成已研究
- 不在本包保存数据库密码

## 2. 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 文件夹 | `electronics_research_agent/`（ASCII） | 避免 Windows / Python 导入问题；显示名仍用中文 |
| 组织树 | 申万电子全树（1+6+16） | 编制一次建齐，以后加股票只开槽位 |
| v1 宇宙 | `valuation_inputs` 中 17 只不重复股票 | 与现网估值表对齐，不摊薄到全市场 |
| 估值引擎 | 不调用路由引擎，用电子政策卡 | 按行业单独估值 |
| 编排器 | 确定性代码，不是 LLM | 分派和隔离不能靠模型自觉 |
| 信息流 | 严格自下而上、上级看不到原始个股卡 | 逼每一级做抽象，而不是三层复述同一张财报 |
| LLM | 默认 `llm.enabled=false` | 先跑通数据装配与工件树，再填叙事 |
| 密码 | 仅 `VR_PG_PASSWORD` / `.env` | Postgres 是外部服务，不是文件夹依赖 |

  │    ├─ 品牌消费电子 (270503) / 消费电子零部件及组装 (270504)

| 层 | 内容 | 作用 |
|----|------|------|
| 组织树 | 1 个 L1、6 个 L2、16 个 L3 | 文件夹和角色一次建齐 |
| 活跃宇宙 | 17 只股票、3 个 L2、7 个 L3 | 真正跑研报、接库、出数 |

stub 节点有人设、有空综述、不接票，禁止从其它板块借股票凑数。

## 4. 一二三级如何配合

### 4.1 总原则

固定汇报链，不是互相聊天的自由集群：

```text
宇宙 17 票
    ↓ 按 L3 分派（编排器，不是首席）
L3 研究员写出个股卡 + 三级综述
    ↓ 只把综述交给直属主管
L2 主管核对政策、做本二级对比
    ↓ 只把二级综述交给首席
L1 首席做跨二级比较和关注优先级
```

股票不会「找首席」。`002371` 北方华创只能进半导体设备研究员。

### 4.2 职责与禁区

| 角色 | 必须做 | 禁止 |
|------|--------|------|
| 研究员 | 本三级成分股的经营事实、财务/估值情景、class_name 与申万差异 | 定估值政策；看隔壁三级的票；用表内分类覆盖申万 |
| 主管 | 抽检下属政策是否用对；本二级内相对位置；驳回越权 | 改个股原始数字；给目标价；把非下属 L3 拉进来 |
| 首席 | 电子周期总纲；三个活跃 L2 的相对景气与估值锚是否一致；点名冲突 | 打开个股卡；写买卖指令；把 stub 主管当成已覆盖 |
| 编排器 | 映射、拉数、隔离输入、写工件、校验结构 | 自己做行业判断 |

### 4.3 信息隔离

上级看不到下级的原始材料，下级看不到兄弟板块。

```text
研究员 270108 半导体设备
  能看：北方华创、长川科技；设备政策卡（EV_EBITDA 主）
  不能看：长电、深南、鼎龙

主管 270100 半导体
  能看：设备 / 分立 / 封测 / 材料 四份 L3 综述 + 半导体政策
  不能看：四家公司的原始个股卡；也不能看 PCB

首席 270000 电子
  能看：半导体、元件、电子化学品Ⅱ 三份主管综述
  不能看：任何个股卡
```

### 4.4 估值政策在层级间传递

政策不是 agent 讨论出来的，是 `data/specs/electronics_specs.yaml` 里的静态卡。研究员可引用不可改。冲突由首席点名，改卡只能改 specs 文件。

半导体最能说明 L2 与 L3 的配合：

| 申万 L3 | 切片 | 主指标 | v1 |
|---------|------|--------|----|
| 数字/模拟芯片设计 (270104/270105) | `fabless` | PE_TTM，禁 PB | stub |
| 集成电路制造 (270106) | `foundry` | PB_TBV，禁 PE_FWD/PEG | stub |
| 半导体设备 (270108) | `equipment` | EV_EBITDA | 北方华创、长川科技 |
| 集成电路封测 (270107) | `packaging` | EV_EBITDA | 长电科技、晶方科技 |
| 分立器件 (270102)、半导体材料 (270103) | **无切片** | 跟随 L2 PE，标明「未切片」 | 扬杰/捷捷；江丰/雅克 |

二级默认链：

| L2 | 主链 | 备选 |
|----|------|------|
| 半导体 / 元件 / 消费电子 | PE_TTM → EV_EBITDA → PB | PEG |
| 光学光电子 / 其他电子Ⅱ / 电子化学品Ⅱ | EV_EBITDA → PE_TTM → PB | — |

配合顺序：编排器按股票 L3 取政策卡写入个股卡 → 主管审阅（设备组是否误用设计股 PE；材料组是否漏写「未切片」）→ 首席看三个二级的锚是否矛盾。

### 4.5 分类冲突（研究员必须写、主管必须盯）

表内 `class_name=3985电子专用材料制造` 在申万里被拆开，**以申万为准**：

| 股票 | 申万归属 | 负责研究员 |
|------|----------|------------|
| 002409 雅克科技 | 半导体 / 半导体材料 | `270103` |
| 300054 鼎龙、300236 上海新阳、300346 南大光电 | 电子化学品Ⅱ / 电子化学品Ⅲ | `270601` |

化学品主管若发现雅克被写进本三级，必须驳回。

## 6. 目录与运行时边界

```text
electronics_research_agent/
  config/
    settings.yaml           # 活跃槽位、切片映射、playbook 索引
    db.yaml                 # 主机/库名，无密码
    playbooks/              # 12 个角色手册（首席/主管/研究员/stub）
  data/                     # 电子子集 + 政策卡 + 宇宙
    sw2021/                 # 电子 L1/L2/L3 + 成分股
    specs/                  # 电子政策卡（6 L2 + 4 L3 切片）
    universe/               # v1 17 票
  src/electronics_research_agent/
    taxonomy/               # 代码 → 申万（codes/sw/map_stock/universe）
    policy/                 # 读政策卡（policy_for）
    db/                     # 只读估值表（client/queries）
    agents/                 # 角色、playbook、允许的工具
    orchestrator/           # 分派、汇总、CLI（dispatch/aggregate/run）
    artifacts/              # 个股卡 / L2 综述 / L1 简报（schema/render）
    config.py / paths.py / io_util.py / __main__.py
  tests/                    # 5 个测试（含禁止路由引擎 import）
  runs/                     # 每次研报输出（gitignore）
  pyproject.toml / requirements.txt
```

约定：

- `src/` 禁止出现 `valuation_router`（`test_no_parent_imports.py` AST 守）
- 所有路径相对本包根目录（`paths.py`）

本集群自带电子子集与政策卡；全市场申万分类真源在研究院 `industry_data/sw2021/`。

## 7. 模块职责

| 模块 | 做什么 |
|------|--------|
| `taxonomy` | 申万树、成分表、v1 宇宙；`map_stock` 优先宇宙、否则成分 CSV |
| `policy` | `policy_for(l2, l3)`：有切片用 L3 卡，否则 L2 + 「未切片」备注 |
| `db` | 只读 `valuation_inputs` / `valuation_summary` / `vr_industry_sw` / `vr_finance_snapshot` |
| `agents.roles` | `build_org()` 构建 1 首席 + 6 主管 + 16 研究员 |
| `agents.prompts` | 装 playbook markdown |
| `agents.tools` | 映射、政策、本 L3/L2 宇宙；给未来 LLM 用，当前由编排器调用 |
| `orchestrator.dispatch` | 股票按 L3 分组 |
| `orchestrator.aggregate` | 组装 L3 笔记 → L2 综述 → L1 简报 |
| `orchestrator.run` | CLI：`map` / `tree` / `universe` / `run` |
| `artifacts` | `CompanyCard` / `L3Note` / `L2Review` / `L1Brief` / `RunManifest` 渲染 Markdown + JSON |

一次 `run`：读宇宙与编制 → 可选连库拉 17 票 → 每个 L3（含 stub）写 note → 每个 L2 写 review（只读下属 L3 综述）→ 首席写 brief（只读 L2 综述）→ 写 manifest.json。

当前 `llm.enabled=false`：数字和归属填实，叙事为「待撰写」。接 LLM 时不改汇报链，只替换叙事正文。

## 9. 现状与下一步

**已落地**

- 编制、分派、隔离规则、政策卡、自下而上工件
- 17 票正确交到对应研究员，再滚到主管和首席
- 设备/封测走 EV_EBITDA 切片；分立/材料标明跟随二级 PE
- `3985` 拆分写在个股卡上，雅克不进入化学品Ⅲ
- 包内测试（含禁止路由引擎 import）；可选连库富化内在价值/现价

**未做（同一套协议上的下一步）**

1. 接 LLM：研究员 → 主管 → 首席按 playbook 写叙事
2. 主管驳回 → 研究员重写的循环（仍只允许直属上下级）
3. 扩展宇宙到电子全市场成分（会摊薄深度，需单独决策）

驳回规则预留：只能发生在直属上下级之间；首席仍然不能直接改个股卡。
