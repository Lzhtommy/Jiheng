## 0. 一句话

做**通用的电子一级行业（申万 270000）agent 集群**：编制覆盖全树，宇宙默认用电子全成分；编排器按 L3 分派，政策卡定口径，L3 → L2 → L1 自下而上汇总。  
**17 只票只是测试夹具，不是产品边界。**

## 1. 对旧设计的结论（先定调，再写新方案）

### 1.1 v0.1 哪里对

| 保留 | 原因 |
|------|------|
| 申万 电子 L1/L2/L3 作为编制真源 | 角色与分类对齐，加票只开槽位 |
| 政策卡 YAML，运行中不可改 | 设备 / 设计 / 制造口径不可混 |
| 编排器是代码，不是行业角色 | 分派与装配不能靠模型自觉 |
| L3 → L2 → L1 汇报链 | 每一级做抽象，而不是三层复述 |
| 关 LLM 也能跑结构化工件 | 先通数据与契约，再填叙事 |

### 1.2 v0.1 / v0.2 方案哪里不对（本版不再继承）

| 问题 | 表现 | 新方案态度 |
|------|------|------------|
| 把测试集写成产品 | 宇宙冻结 17 票；文档处处「三个活跃 L2」「stub 不借票」 | 宇宙 = 电子成分；17 票仅 fixture |
| 活跃/stub 绑死在测试覆盖 | settings 写死 3 个 L2 / 7 个 L3 | 有成分就有岗位；本轮无票则空跑，不叫 stub 产品态 |
| 隔离写过头 | 大段「不能看隔壁」「首席不能打开个股卡」「钻取一次且审计」 | 隔离由分派自然产生；不另造穿透工具与原因码百科 |
| 为未发生的错误立法 | 雅克/3985、stub 污染、借票等写进架构与验收主叙事 | 分类以申万为准即可；个案放测试，不进宪法 |
| v0.2 叠床架屋 | CycleClock + ChainFact 黑板 + LangGraph 状态机 + Harness 案例库 + reason_code 表 | 本版不做；需要时另立项，不绑进 v0.3 主干 |
| 「保留并强化 v0.1」当目标 | 把错误边界也强化了 | 对的留下，错的丢掉，不背书旧稿 |

v0.2 若仍有参考价值，只取其「政策是宪法、分派是代码」两句；**其余机制不迁入本文。** v0.2 原文保留在 `ELECTRONICS_AGENT_CLUSTER_REDESIGN.md`。

## 2. 目标与非目标

### 2.1 目标

1. **通用电子集群**：申万电子全树（1 L1 + 6 L2 + 16 L3）编制齐全；默认研究宇宙 = `members_electronics.csv` 中的电子成分股（当前约数百只，以文件为准）。
2. **测试与生产分离**：`fixtures/universe_17.yaml`（可由现 `valuation_inputs_v1.yaml` 改名/迁出）仅用于 CI 与本地冒烟；默认 `run` 不读它。
3. **最小充分边界**：研究员只处理本 L3 分到的票；主管只汇总直属 L3；首席只汇总各 L2。边界来自分派结果，不来自额外隔离框架。
4. **政策单一事实源**：`electronics_specs.yaml`；有 L3 切片用切片，否则用 L2 默认链并标记「未切片」。
5. **可扩展跑批**：支持全量、按 L2/L3、按股票列表、按 fixture；输出同一套工件契约。
6. **LLM 可选**：关则数字与归属填实、判断字段 `pending`；开则只替换判断/叙事字段，不改汇报链。

### 2.2 非目标（本方案明确不做）

- 不覆盖其它申万一级行业（那是研究院其它集群的事）
- 不调用全市场 `valuation_router`
- 不写买卖指令、目标价、评级
- 不在包内存数据库密码
- 不设「总 Agent 开会」、不让角色自由互聊
- **不做** v0.2 中的 CycleClock / ChainFact 黑板 / LangGraph 直属状态机 / 受治理案例库 / `view_raw_card` 钻取门闩——这些不是通用集群的前提；以后若真有 SOP 缺口，单独写增量方案
- 不把「像卖方研报」当验收标准

## 3. 产品边界：宇宙与编制

### 3.1 两套名单，职责不同

| 名单 | 路径（建议） | 用途 |
|------|--------------|------|
| **生产宇宙** | `data/sw2021/members_electronics.csv`（+ 可选 filter） | 默认跑批；电子全成分 |
| **测试夹具** | `data/fixtures/universe_smoke_17.yaml` | pytest / `--universe fixture:smoke_17`；回归分派与政策 |

禁止再把夹具写成「v1 覆盖范围」或「活跃宇宙」。README / DESIGN 中的「17 只」一律改为「冒烟夹具」。

### 3.2 编制

```text
首席  电子 (270000)
  ├─ 主管 半导体 (270100)
  │    └─ 16 个 L3 中属于本 L2 的研究员（设备/设计/制造/封测/材料/分立…）
  ├─ 主管 元件 (270200)
  ├─ 主管 光学光电子 (270300)
  ├─ 主管 其他电子Ⅱ (270400)
  ├─ 主管 消费电子 (270500)
  └─ 主管 电子化学品Ⅱ (270600)
```

- 岗位按申万树**一次建齐**，与「本轮有没有票」无关。
- 本轮某 L3 分到 0 只股票 → 产出空 note（`n_companies=0`），标注「本轮无持仓/无成分入选」，**不是永久 stub 产品态**。
- 不再维护「活跃 L2/L3 白名单」作为业务真相；若需限流，用**运行参数**（见 §6），不改组织宪法。

### 3.3 股票如何进槽

```text
输入股票集合 U（默认 = 电子成分 ∩ 可选过滤）
    → 映射到申万 L3（成分表优先；冲突以申万为准）
    → 按 L3 分派给对应研究员
    → 汇总到 L2 主管 → L1 首席
```

映射规则（实现约束，不是叙事）：

1. 代码落在电子成分表 → 用表内 L2/L3。
2. 表外但显式传入的代码 → 拒绝或标 `unmapped`（由 CLI 开关决定），**禁止**静默塞进「其他电子」。
3. 外部行业字段（如表内 `class_name`）只作对照备注，**不覆盖**申万归属。

个别历史争议（例如同一外部分类在申万落到不同 L3）用成分表 + 测试断言解决，不在方案正文展开案例故事。

## 4. 角色：判断类型，不是隔离剧场

角色成立条件：输入不同、输出字段不同、越权能被**分派结果**证伪。  
不成立条件：靠长篇「禁止看见」清单维持人设。

| 角色 | 判断对象 | 输入（仅此） | 输出 |
|------|----------|--------------|------|
| 编排器（代码） | 无 | 宇宙、树、specs、库 | 分派、注卡、裁剪上下文、落盘 |
| 研究员 L3 | 本 L3 公司事实与估值情景 | 本 L3 股票包 + 本政策卡 | CompanyCard* + L3Note |
| 主管 L2 | 本 L2 内相对位置与口径是否一致 | 直属 L3Note（结构化）+ L2 政策 | L2Review |
| 首席 L1 | 电子整体与各 L2 相对位置 | 各 L2Review（结构化） | L1Brief |

\*CompanyCard 默认留在 L3 工件目录；上交的是 L3Note 摘要字段，不是「绝对禁止上级看见文件」。上级若打开原始卡，属于人工阅览，系统不为此发明钻取 API。

### 4.1 所谓「隔离」到底要什么

只要三件事：

1. **分派隔离**：编排器给研究员的上下文 = 该 L3 的股票与卡；不塞其它 L3 的包。
2. **汇总隔离**：主管提示词 / 工具默认只收直属 L3Note；首席只收 L2Review。
3. **政策隔离**：每张卡由 `policy_for(l2, l3)` 注入；模型不能改 YAML。

不必再写：兄弟研究员「不能看」、首席「不能打开个股卡」、主管「最多钻取一次」——分派已经决定可见面；多写的禁令是冗余，还诱导实现假门闩。

### 4.2 主管要不要看个股数字

要核对离谱数字时：看 L3Note 里已经上送的关键字段（估值情景、主指标、异常标记）即可。  
L3Note schema 应带齐主管质控所需标量，而不是先藏光再开 `view_raw_card`。

## 5. 估值政策

保持最硬的一条：**政策不是讨论出来的。**

1. 真源：`data/specs/electronics_specs.yaml`。
2. 有切片的 L3（如设备 / 封测 / fabless / foundry）用 L3 卡；无切片则 L2 默认链 + `unsliced=true`。
3. 本轮只引用，不覆写。研究员可附 `policy_change_request`（建议、原因、影响范围）进待审队列；**人改 YAML 后下一轮生效**。
4. 主管抽检：主指标是否与卡一致、未切片是否声明。不抽检「是否符合市场叙事」。

L2 默认链与 L3 切片内容沿用现卡（实现细节见 `data/README.md`），本文不重复抄表。缺切片的三级保持「跟随 L2 + 未切片」，需要独立卡时改 YAML，不改编排逻辑。

## 6. 运行模型

### 6.1 CLI 形态（目标）

```bash
# 生产默认：电子成分全量（可加过滤）
python -m electronics_research_agent run
python -m electronics_research_agent run --l2 270100,270200
python -m electronics_research_agent run --l3 270108
python -m electronics_research_agent run --codes 002371,300054

# 测试夹具
python -m electronics_research_agent run --universe fixture:smoke_17 --no-db

# 只读工具
python -m electronics_research_agent tree
python -m electronics_research_agent map --codes 002371
python -m electronics_research_agent universe              # 打印生产宇宙规模与按 L3 计数
python -m electronics_research_agent universe --fixture smoke_17
```

### 6.2 一次 run

```text
0. 读树、specs、选定宇宙 U
1. 映射 U → L3；未映射按策略失败或剔除
2. 按 L3 分组；注入政策卡；拉库（可选）
3. 每个有票或空的 L3 写 L3Note（空则 n=0）
4. 每个 L2 写 L2Review（汇总直属 L3Note）
5. L1 写 L1Brief（汇总 L2Review）
6. 写 Manifest（宇宙来源、过滤条件、specs 版本、库快照、llm 开关）
```

关 LLM：结构与数字落地，叙事/判断 = `pending`。  
开 LLM：按 L3 → L2 → L1 顺序填判断字段；仍无跨级聊天。

### 6.3 直属打回（可选，P2）

若需要质控环：仅允许「主管 → 直属研究员」「首席 → 直属主管」带简短原因重跑**该槽**一次或两次。  
实现可以是编排器循环，不必先上 LangGraph。不设原因码枚举表也能做；有枚举更好，但不是架构前提。

## 7. 工件契约（精简）

| 工件 | 必有 |
|------|------|
| CompanyCard | 代码/名称、申万 L2/L3、政策 spec_id、关键情景与指标、provenance；叙事可 pending |
| L3Note | 本 L3 覆盖家数、政策行、未切片标记、公司摘要列表、冲突/异常列表 |
| L2Review | 下属 L3 对比结论、政策抽检结果、本 L2 相对位置（可 pending） |
| L1Brief | 各 L2 摘要、跨 L2 冲突点名、关注优先级；**写明本轮宇宙过滤**（全量或子集） |
| RunManifest | 宇宙来源与规模、过滤、specs 版本、as-of、llm、失败槽位 |

一种研究状态，多种渲染（估值备忘 / 风险摘录）从同一状态切，不新增 Agent。

L1Brief 的「样本边界」改为：**本轮实际跑了哪些 L2/L3 / 过滤条件**，而不是写死「缺消费电子所以不算覆盖」。全量跑时边界就是「电子全成分」；子集跑时边界写过滤参数。

```text
electronics_research_agent/
  config/
    settings.yaml          # 去「活跃白名单」业务含义；可留默认 run 过滤的可选配置
```

## 11. 落地顺序

### P0 — 改边界（不接 LLM）

1. 宇宙默认改为电子成分；17 票迁到 `fixtures/`。  
2. 去掉活跃白名单作为编制真相；run 支持 `--l2/--l3/--codes/--universe`。  
3. 文档与 README 改口：通用集群 + 夹具测试。  
4. 测试按 §9 重写；删掉「stub 产品态」相关断言或改为「空 note」。

### P1 — 契约与规模

5. L3Note 补齐主管质控字段；L1Brief 写本轮过滤边界。  
6. Manifest 记录宇宙来源与规模。  
7. 全量 run 性能：按 L3 并行、库查询批量（实现问题，不改角色模型）。

### P2 — LLM 与可选打回

8. 开 LLM 填判断字段，顺序仍 L3 → L2 → L1。  
9. 可选：直属重跑 1–2 次（编排器循环即可）。

### P3 — 真有缺口再立项（本文不设计）

10. 景气时钟、产业链事实黑板、复杂质控图、跨轮案例库——**仅当 P0–P2 跑通且 SOP 证明缺它们时**另开设计，不预埋进 v0.3。

## 12. 验收（走偏就停）

重构后下列句子必须为真：

1. 默认 run 的宇宙是电子成分（或用户显式过滤后的子集），**不是** 17 票。  
2. 17 票只出现在 fixture 与测试命令里。  
3. 光学 / 消费电子等 L2 有岗位；本轮无票则空 note，而不是「永久 stub、禁止当真」。  
4. 分派决定可见股票集合；方案正文不再维护长篇「不能看谁」清单。  
5. 政策仍只来自 YAML；模型不能改卡。  
6. 关掉 LLM，全量或子集跑批仍能出齐 L3/L2/L1 工件与 Manifest。

少一条，就还在旧的「17 票实验室」或「隔离剧场」里。

## 13. 摘要

| | v0.1 落地 | v0.2 方案（原文另存） | **本方案 v0.3** |
|--|-----------|----------------------|-----------------|
| 宇宙 | 冻结 17 | 保留 17，扩容另立项 | **电子成分；17=夹具** |
| 编制 | 活跃/stub 绑测试 | 强化 stub 纪律 | **全树岗位；空槽空跑** |
| 隔离 | 大段禁令 | 再加钻取/原因码/黑板 | **仅分派+汇总+政策** |
| 质控 | 文字预留 | LangGraph+Harness 全家桶 | **P0 不做；P2 可选轻量打回** |
| 态度 | 实验室覆盖 | 在实验室上叠 SOP | **先成为通用电子集群** |

**宪法用申万树与 YAML 政策卡；边界用分派代码；研究用 L3→L2→L1 工件。**  
不在主干上预埋用不到的隔离与框架。
