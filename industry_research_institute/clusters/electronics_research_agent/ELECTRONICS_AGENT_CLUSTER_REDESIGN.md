# 电子行业研究院 Agent 集群：重构方案

版本：v0.2.0-design  
状态：方案（相对 v0.1.0 DESIGN 的重构，尚未落地）  
对应目录：`industry_research_institute/clusters/electronics_research_agent/`  
上游文档：`DESIGN.md` v0.1.0

本文回答：在保留 v0.1 编制与隔离的前提下，如何补齐自上而下时钟、有限交叉印证、直属反馈、以及「同一类错误第二次被拦住」。关键问题给出当前最有效的框架，而不是再发明一套总 Agent。

---

## 0. 一句话

集群的产品是**可验收的研究状态**，不是「几个 Agent 开会写研报」。

编排器管边界，角色管判断类型，工件管交接，LangGraph 只管本轮直属打回，Harness 管跨轮不再犯，人管宪法（申万树与政策卡）。

---

## 1. 重构目标与非目标

### 1.1 目标

1. 保留并强化 v0.1：申万编制、17 票分派、政策卡单一事实源、信息隔离、stub 不借票、编排器不是行业角色。
2. 补齐真实行研 SOP 中与电子行业相关的三股信息流：
   - 向下：版本化景气时钟（前提可下发）
   - 横向：限额 ChainFact 黑板（事实可共用、材料不可共用）
   - 向上：带原因码的直属驳回（结论可顶回去）
3. 把「上级觉得不好」从写进自己作业，改成可审计的质控环。
4. 把「别再犯第二次」做成闸门，而不是模型记忆。
5. 产出从空叙事模板，升级为带假设 / 冲突 / 证伪 / 样本边界的研究底稿；报告只是底稿的渲染。

### 1.2 非目标（本方案仍然不做）

- 不覆盖其它一级行业
- 不调用 `valuation_router.route()`
- 不把消费电子 / 光学光电子等 stub 写成已覆盖
- 不在包内保存数据库密码
- 不让 Agent 互聊、不设总 Agent 开会
- 不写对外买卖指令 / 目标价 / 评级
- 不让模型运行中改政策卡或改隔离规则
- 不把「像卖方研报」当作验收标准
- 不把宇宙一次性扩到电子全市场成分（另立项）

### 1.3 对 v0.1 的态度

| 保留 | 改 | 新增 |
|------|----|------|
| 组织树 1+6+16 | 单向交卷 → 有限双向 | CycleClock |
| 活跃宇宙 17 票 | L1/L2/L3 必填字段 | ChainFact 黑板 |
| 政策卡 YAML | 一次 run 的阶段划分 | 直属驳回状态机 |
| 信息隔离默认成立 | Manifest 增加原因码与钻取审计 | Eval Harness + 反例夹具 |
| 编排器确定性分派 | 接 LLM 只填叙事与判断字段 | 跨轮案例库（受治理写入） |
| stub 纪律 | L1 强制样本边界 | 运行时可选 LangGraph 子图 |

## 2. 关键问题与最有效框架

重构不选「一个万能框架」，按问题选层。这是本方案的技术宪法。

| 关键问题 | 最有效框架 | 不采用 | 理由 |
|----------|------------|--------|------|
| 谁看哪些票、用哪张政策卡 | **确定性编排器 + 静态 specs** | 总 Agent 分活、模型认领 | 分派和口径不能靠自觉 |
| 异构估值（设备 EV/EBITDA vs 设计 PE） | **Policy-as-Code（YAML 卡 + 引用不可改）** | 运行中覆写、模型选倍数 | 冲突点名，改卡走人审 |
| 防止三层复述同一张财报 | **信息隔离墙（按角色裁剪上下文）** | 共享全量 Context | 角色 = 可见面，不是工牌 |
| 电子产业链交叉印证 | **黑板 / Blackboard：限额 ChainFact** | 兄弟 Agent 自由对话 | 事实可共用，原始卡不可共用 |
| 周期定调与个股对表 | **版本化 Clock 作为只读输入** | 首席先定调且下级必须贴合 | 前提可下发，结论可顶回去 |
| 上级觉得下级做得不好 | **LangGraph 直属状态机**（draft→review→reject→rewrite） | 群评、首席改个股卡 | 只解决本轮质控 |
| 数字离谱时主管要核对 | **有门闩的工具调用** `view_raw_card` | 主管默认可见全部个股卡 | 隔离是默认，穿透要留痕 |
| 同一类错误第二次出现 | **Eval Harness + 反例回归 + CI 门禁** | Reflexion、通用 Memory、图自我改规则 | 结构性错误必须在进模型前失败 |
| 判断性错误的跨轮提醒 | **受治理的案例库（CBR 的窄用）** | Mem0 一类自动记忆升格为规则 | 模型可提议教训，不能写宪法 |
| 接 LLM 后 Context 膨胀 | **Pydantic / JSON 契约向上传** | 把 L3 长文直接喂 L2/L1 | 上级吃结构化摘要，不是全文 |
| 系统是否在进化 | **人改 specs + 测试变绿** | 让图优化自己的边或政策 | 裁判与选手必须分开 |

一句话对照：

- **LangGraph**：本轮怎么打回去  
- **Harness + 夹具**：怎么保证换模型后旧错回不来  
- **政策卡 + 隔离**：怎么让整类错误发生不了  
- **黑板 + 时钟**：怎么在不拆墙的前提下接近电子组 SOP

## 3. 总体结构

```text
                    ┌─────────────────────────────────────┐
                    │  宪法层（只读，人改）                  │
                    │  申万树 / electronics_specs.yaml     │
                    │  宇宙冻结名单 / playbook / 隔离规则    │
                    └─────────────────────────────────────┘
                                      │
                    ┌─────────────────────────────────────┐
                    │  闸门层 Harness（代码，进图前）        │
                    │  分派校验 · 政策命中 · 隔离泄漏       │
                    │  stub 污染 · 反例回归 · CI           │
                    └─────────────────────────────────────┘
                                      │
     CycleClock（版本化只读）          │
     ChainFact Board（只写限额事实）    │
                                      ▼
                    ┌─────────────────────────────────────┐
                    │  编排器（代码，不是 Agent）            │
                    │  map / dispatch / inject policy      │
                    │  裁剪上下文 / 写 Manifest 骨架        │
                    └─────────────────────────────────────┘
                                      │
                    ┌─────────────────────────────────────┐
                    │  本轮子图 LangGraph（可选，LLM 开时）  │
                    │  L3 write ⇄ L2 review（直属）         │
                    │  L2 write ⇄ L1 review（直属）         │
                    │  reject 必带 reason_code              │
                    │  drill-down 最多一次且审计            │
                    └─────────────────────────────────────┘
                                      │
                    ┌─────────────────────────────────────┐
                    │  工件层                               │
                    │  CompanyCard / L3Note / L2Review     │
                    │  L1Brief / RunManifest / CaseLog     │
                    └─────────────────────────────────────┘
```

三层运行时原则：

1. 关 LLM 时，闸门 + 编排器 + 空叙事工件必须仍能跑通（继承 v0.1）。
2. 开 LLM 时，只把「写判断字段 + 直属审改」放进图。
3. 任何时候图都不能改宪法层。

## 4. 角色：判断权，不是章节

角色成立的条件：不同输入、不同禁区、不同验收字段、越权可被测试抓住。缺一条就退回任务拆解。

### 4.1 编排器（代码）

- 必须：映射股票到 L3、注入政策卡、按角色裁剪上下文、调用闸门、组装工件、写 Manifest。
- 禁止：行业判断、改数字、改卡、替任何一级写结论。

### 4.2 研究员 L3

- 判断对象：本三级成分股事实、财务与估值情景、申万 vs `class_name`、相对时钟的顺/逆/滞后。
- 可见：本 L3 股票、本政策卡、本轮 CycleClock、本轮黑板上与本链相关的 ChainFact（只读）。
- 不可见：兄弟 L3 个股卡、非下属政策讨论、L1 未冻结的口头定调。
- 必须输出：个股卡 + L3Note + 0–5 条 ChainFact + 可选 `policy_change_request`（不影响本轮卡）。
- 禁止：定估值政策、改卡、借用非本 L3 股票、把 stub 写成覆盖。

### 4.3 主管 L2

- 判断对象：下属 L3 是否可比、政策是否用对、本二级相对位置、是否需要打回。
- 可见：直属 L3Note 的结构化摘要、本 L2 政策、CycleClock、黑板。
- 默认不可见：个股卡原文。
- 例外：命中钻取门闩时可 `view_raw_card(stock)` 一次，写入 Manifest。
- 必须输出：L2Review（对比，不是拼接）+ 对下属的 pass/reject。
- 禁止：改个股原始数字、给目标价、拉入非下属 L3、无 reason_code 打回。

### 4.4 首席 L1

- 判断对象：电子周期总纲、三个活跃 L2 的相对景气与锚是否一致、点名冲突、关注优先级。
- 可见：活跃 L2Review 摘要、CycleClock（若本轮时钟来自上轮冻结 L1，须标明版本）、黑板聚合、每份 L2 的锚点数字与冲突清单。
- 不可见：任何个股卡全文；不能把 stub 主管当已覆盖。
- 必须输出：L1Brief + 对主管的 pass/reject + 样本边界声明。
- 禁止：打开个股卡（L1 无钻取权，避免变成总编辑）、写买卖指令、要求下级「贴合我的口风」。

### 4.5 为什么还要分角色

若所有人共享 17 张卡和同一政策菜单，首席/主管/研究员可以合并成三个提示词文件。本方案分角色，是因为电子不可比：设备与三环不能共用判断类型。角色是权限矩阵，不是人设。

## 5. 交互协议

交互模型名称：**确定性编排 + 三种合法通道 + 直属质控图**。  
不是 AutoGen 群聊，不是总 Agent 任务树，也不是整张业务都丢进 LangGraph。

### 5.1 通道 A：向下 — CycleClock

- 对象：一份短、版本化、只读的电子景气钟。
- 建议字段：终端（AI 服务器 / 手机 / PC / 汽车电子）方向、库存、晶圆厂 capex、出口管制强度、时钟版本号与来源。
- 来源优先级：人写前提 > 独立总量槽位 > 上轮已冻结 L1Brief 的时钟段。  
  **禁止**本轮首席先空生成、再要求 L3 叙事贴合。
- L3 必答：相对本钟是顺周期 / 滞后 / 对冲；允许输出 `clock_conflict` 及证据。
- 效果：补 SOP 的自上而下，同时保留「用事实顶回去」。

### 5.2 通道 B：横向 — ChainFact Board

- 每个活跃 L3 最多推送 5 条标准化事实（指标名、方向或区间、时期、来源表/字段、置信度）。
- 禁止上传：估值表全文、目标价、个股叙事、未进宇宙的票。
- L2/L1 及他组 L3 只读；不可评论、不可改写。
- 效果：设备稼动、材料价格、封测先进封装利用率、PCB 服务器板占比可以互相印证，同时个股卡仍隔离。

### 5.3 通道 C：向上 — 工件交接

继承 v0.1：

```text
个股卡（留在 L3 槽位，默认不上交）
    → L3Note 结构化摘要 → 主管
        → L2Review 结构化摘要 → 首席
            → L1Brief
```

上级吃契约字段，不吃「大家好我是设备研究员」长文。

### 5.4 通道 D：打回 — 仅直属，且在图内

```text
首席 --reject(L2)--> 主管重写 L2Review
                       │ 根子在 L3 时
                       └-reject(L3)--> 研究员重写 L3Note
                                        必要时 view_raw_card ×1
```

- 首席不直接打 L3，不改个股卡。
- 同一边每轮最多 2 次 reject。
- 无 reason_code 的不满意，只能写进本层「冲突/保留意见」，不触发重跑。

## 6. 工件与输出形态

### 6.1 原则

一种研究状态，多种出口。不按「研究报告 / 估值报告 / 风险报告」再养 Agent。

### 6.2 必选工件

| 工件 | 新增必填（相对 v0.1） | 不是什么 |
|------|----------------------|----------|
| CompanyCard | 政策卡 id、申万 vs class_name、三情景位、关键假设、证伪条件、数据 provenance | 对外公司深度 |
| L3Note | 时钟应答、未切片声明（如适用）、ChainFact 列表、冲突草稿 | 三级行业年报 |
| L2Review | 下属政策抽检表、本二级相对位置、打回记录、对比结论（禁止只拼接） | 二级深度 |
| L1Brief | 三 L2 锚是否一致、冲突点名、关注优先级、**样本边界**（缺消费电子/光学） | 配置下单备忘 |
| RunManifest | 宇宙版本、specs 版本、时钟版本、库快照、reject 列表、钻取列表 | — |
| CaseLog | 本轮进入案例库的失败（见 §8） | 通用记忆 |

### 6.3 可选切片（同一状态渲染，不新增角色）

- 估值备忘：从卡片情景 + 政策卡 + 分位字段切出  
- 风险备忘：从证伪条件 + 管制/供给 ChainFact 切出  
- 增量点评：两次 Manifest diff 非空字段切出  

未接 LLM 时，数字与归属填实，判断字段可为 `pending`，但结构必须在。

## 7. 估值政策治理

保持 v0.1 最硬的一条：**政策不是讨论出来的。**

1. 本轮只使用 `electronics_specs.yaml` 写入的卡。  
2. 设备 / 封测：EV_EBITDA；设计：PE_TTM（仍 stub）；制造：PB_TBV（仍 stub）；分立 / 材料：跟随 L2 PE 并标明未切片。  
3. 3985 拆分以申万为准：雅克 → 270103；鼎龙 / 新阳 / 南大光电 → 270601。  
4. L3 可输出 `policy_change_request`（建议锚、原因、影响股票），**本轮不覆写**。  
5. 请求进入待审队列，人改 YAML 后才在下一轮生效。  
6. 后续可把「如何用指标」写入卡，而不是只写「用哪个指标」：peer 准入、禁令、历史分位、何时启用备选链。本方案把这一项列为 v0.2.1，不阻塞反馈环。

主管抽检先查：用错主指标、漏写未切片、把雅克写进化工。不查「是否符合炒作主线」。

## 8. 反馈环与防再犯

### 8.1 本轮：LangGraph 子图

节点建议（实现时可合并，语义不可少）：

```text
validate_in → L3_write → extract_chainfacts
    → L2_review → (pass | reject_L3 | drill_then_decide)
        → L2_write → L1_review → (pass | reject_L2)
            → finalize → harvest_cases
```

状态至少包括：工件引用、reason_code、reject_count、drilled_stocks、clock_version、specs_version。

reason_code 先做死，不允许自由文本当唯一原因：

| 码 | 含义 | 典型触发 |
|----|------|----------|
| `policy_mismatch` | 政策卡用错 | 设备组主指标写成 PE |
| `taxonomy_error` | 申万归属错 | 雅克出现在 270601 |
| `borrowed_ticker` | 借用非本槽位股票 | PCB 写进光学 stub |
| `missing_unsliced_flag` | 未切片未声明 | 材料组跟 L2 PE 但没写 |
| `stub_as_covered` | stub 当已覆盖 | L1 把消费电子写成结论来源 |
| `number_narrative_conflict` | 数字与叙述矛盾 | 增速与表内字段冲突 |
| `clock_unanswered` | 未应答时钟 | L3 没有顺/逆/滞后 |
| `isolation_leak` | 上下文越权 | 主管输入含个股卡字段 |

仅当 `number_narrative_conflict` 或校验器标出的数值越界时，L2 可调用 `view_raw_card`。调用一次、一票、记审计。L1 无此工具。

### 8.2 跨轮：Harness，不是图的记忆

防再犯采用三件套，这是目前对结构性错误最有效的结构。

**A. 架构闸门（发生不了）**  
分派表、政策注入、上下文裁剪、stub holdings=`[]` 全是代码。模型没有「把雅克塞进化工」的合法通道。

**B. 反例回归（换模型也回不来）**  
固定夹具进 CI，至少包括：

- 17 票 100% 进对 L3  
- 002409 ∉ 270601 宇宙  
- 270108 政策主链 = EV_EBITDA  
- L2 输入 schema 不含个股级原始财务字段  
- 光学 / 消费电子等 stub 的 holdings 为空  
- L1Brief 含样本边界字段  

断言失败：禁止发布，不必进图。

**C. 受治理案例库（判断性错误的提醒）**  
`harvest_cases` 只收带 reason_code、且重写后该码消失或仍失败的记录。下一轮同 L2/L3 槽位可检索「本槽历史失败约束」作为只读附加输入。  
写入规则：Agent 可提议，Harness 校验字段完整才落库；**任何案例都不能自动改 specs**。过期、撤销、作用域（只对某 L3）必须可查。

### 8.3 明确无效的做法

- 只靠 Reflexion：「上次写得不好，这次注意」  
- 通用会话记忆把观点写成规则  
- 让 LangGraph 根据评分改自己的边或改 YAML  
- 用「首席满意度」当回归指标

## 9. 一次 run 的阶段

```text
0. 读宪法：树 / 宇宙 / specs / 上轮冻结时钟
1. 闸门预检：夹具 + 分派 + 隔离 schema
2. 编排器分派、注卡、裁剪上下文、挂载时钟与黑板只读视图
3. （llm.off）代码填数字与归属，判断字段 pending，跳到 5
   （llm.on）进入 LangGraph 子图：写 → 审 → 有限打回
4. 提取 ChainFact，写 CaseLog 候选
5. 聚合 L2 / L1（若图内已完成则只做落盘校验）
6. 闸门后检：隔离泄漏、stub 污染、L1 样本边界、Manifest 完整
7. 计算与上轮 diff，写入 runs/{id}/
```

失败策略：闸门失败 fail-closed；图内超过 reject 上限则该槽标记 `unresolved`，仍落盘但不进入「已覆盖」统计。

## 10. 指标

主指标对准事故，不对文笔。

| 层 | 指标 | 目标 |
|----|------|------|
| 闸门 | 分派准确率 | 100% |
| 闸门 | 政策命中率 | 100% |
| 闸门 | 隔离泄漏率 | 0 |
| 闸门 | stub 污染率 | 0 |

## 13. 验收场景（方案是否走偏）

重构后下列句子必须仍为真：

1. 002371 北方华创只能进 270108，进不了首席桌子，也进不了化学品组。  
2. 002409 雅克不会因为「更像电子化学品故事」改归属。  
3. 设备组 EV/EBITDA 与材料组未切片 PE 并存时，L1 必须能点名，而不是两份顺畅综述。  
4. 关掉 LLM，分派、政策、隔离、stub、diff 仍能跑。  
5. 主管「不喜欢这段话」若无 reason_code，不能迫使研究员重写。  
6. 案例库不能把上次的错误例外写成这次的政策卡。

六条少一条，就是把集群开回改稿会议或通用多智能体。

## 14. 摘要

v0.2 不替换 v0.1 的研究所编制，只补四块：

1. **时钟**把 SOP 的自上而下接进来，且允许顶回去。  
2. **黑板**把电子传导接进来，且不拆隔离墙。  
3. **LangGraph 直属图**把「觉得不好」变成可审计打回。  
4. **Harness + 反例 + 受治理案例库**把「第二次」挡在进模型之前。

关键问题的框架选择已经收敛：**宪法用 YAML，边界用代码，本轮用图，跨轮用测试。** 不在这四层之外再找一个更智能的总 Agent。
