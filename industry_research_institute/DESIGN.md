# 行业研究院：设计思路与方案

版本：v0.2.0

电子集群内部的一二三级配合见 `clusters/electronics_research_agent/DESIGN.md`。

---

## 1. 目标

做「大的行业研究院」：每个申万一级行业有自己的首席 / 主管 / 研究员集群，并**按行业单独估值**。

两层分工：

| 层 | 放什么 | 谁用 |
|----|--------|------|
| 研究院（本目录） | 申万全市场数据源、拉数作业 | 所有行业集群共用分类树与财务数据管道 |
| 集群 `clusters/<industry>/` | 该一级的组织、playbook、宇宙、本行业估值政策 | 只跑本行业研报与估值 |

电子集群自带电子子集 `data/`，不调用路由引擎。

---

## 2. 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 共享数据 | `industry_data/sw2021/` 全量 | 分类树、成分、刷新脚本是各行业集群的共同输入 |
| 拉数 | `jobs/` 行业 / 财报 / 一致预期作业 | 估值输入依赖这些表 |
| 估值 | 按行业单独估值，不调用全市场路由 | 各行业估值口径差异大，路由归一化反而失真 |
| 个股估值数字 | 仍在 Postgres | 活数据，不冻结进 git |
| 密钥 | 作业只读 `VR_PG_PASSWORD` | 不保留明文密码 |

---

## 3. 与电子集群的关系

```text
行业研究院
  ├─ 共享数据：申万 31 个 L1 / 134 个 L2 / 346 个 L3 + 成分
  ├─ 共享作业：行业分类、同花顺财报、一致预期
  └─ clusters/electronics_research_agent
       ├─ 电子子集（1 个 L1 / 6 个 L2 / 16 个 L3）
       ├─ v1 宇宙 17 只股票
       └─ 首席 / 主管 / 研究员；本行业自己的估值政策卡
```

电子跑批仍是：股票 → L3 研究员 → L2 主管 → L1 首席。
研究院不参与汇报链，只提供分类真源和拉数。

---

## 4. 加新行业集群

1. 从 `industry_data/sw2021/registries` 裁该 L1 的 L2 / L3
2. 从成分 CSV 滤该 L1 成员
3. 在该集群内写本行业估值方法
4. 冻结 v1 宇宙，写首席 / 主管 / 研究员 playbook
5. 需要刷新行业或财报时，用本目录 `jobs/`

---

## 5. 数据分三处

| 位置 | 内容 |
|------|------|
| `industry_data/sw2021/` | 全市场分类与成分（文件，入版本库） |
| `jobs/` | 把外部数据写入 Postgres 的作业脚本 |
| `clusters/*/data/` | 该行业裁剪后的树与宇宙（文件，入版本库） |
| Postgres | `valuation_inputs`、`valuation_summary`、`vr_industry_sw`、`vr_finance_snapshot`、`vr_ths_*`、`vr_consensus_*`、`vr_sector_em` 等活数据 |
